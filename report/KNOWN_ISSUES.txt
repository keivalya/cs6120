1. FABRICATED RQ4 / RQ5 / RQ6 REMOVED  (resolved)
--------------------------------------------------------------------------------
The prior paper draft presented three headline contributions built on
synthetic, hardcoded data rather than measurements:

  - RQ4 "Mechanistic Attention Allocation (AAR), 12.14x": produced by
    analyze/attention_mechanics.py from closed-form curves
    (noun_attn = 0.40 + 0.20*(l/16) + 0.03*sin(l); verb_attn = 0.38*exp(...)).
    No model was ever loaded or probed.
  - RQ5 "ICAG mitigation, +23.8 pp": produced by analyze/guided_mitigation.py
    from a hardcoded Python dict. No guided inference was ever run.
  - RQ6 "Long-Horizon LIBERO-10": produced by analyze/horizon_generalization.py
    from a literal list. LIBERO-10 was never run (configs/grid.yaml only ever
    lists suites: [libero_goal]; results/ contains no libero_10 directory).

Copies of these generators/outputs had already been quarantined under
archive/fabricated/, but the same numbers were still shipping in report/ and
were presented as measured results in report/paper_acl.tex, report/compile_acl.py,
report/make_slides.py, and report/dashboard.html.

Actions taken:
  - Deleted report/rq4_attention.{csv,png}, rq5_mitigation.{csv,png},
    rq6_horizon.{csv,png}.
  - Deleted the live generators analyze/{attention_mechanics,guided_mitigation,
    horizon_generalization}.py. (archive/fabricated/ is kept only as an internal
    record and is NOT included in the release bundle allowlist in
    report/make_release.py.)
  - Removed the RQ4/RQ5/RQ6 sections and their contribution bullets from
    report/paper_acl.tex, and corrected the Experimental Setup (LIBERO-Goal only),
    Discussion, and Conclusion to claim only what RQ1-RQ3 support.
  - Cleaned the same fabricated claims from report/compile_acl.py,
    report/make_slides.py, and report/dashboard.html.
  - Removed the stale committed PDFs (report/paper.pdf, paper_acl.pdf,
    slides.pdf) because they embed the fabricated numbers and could not be
    rebuilt in the current environment (no pdflatex/reportlab). They must be
    regenerated from the cleaned sources on a machine with LaTeX before use.

RQ4 (real cross-attention extraction) and RQ5 (real inference-time contrastive
guidance) are intended to be reinstated ONCE MEASURED on-device. RQ6 (LIBERO-10)
is out of scope for the near-term submission.

5. RQ4 ATTENTION  (OPEN — the shipped CSV covers 2 models, not 3)
--------------------------------------------------------------------------------
CORRECTION (2026-07-29). This section previously stated that RQ4 "is REAL". That
was too strong and is now known to be wrong for one of the three models. What the
committed report/rq4_attention.csv actually contains:

  (a) DUPLICATED MODEL BLOCK — SHIPPED, NOW BEING RE-MEASURED. The openvla_oft
      rows are BIT-IDENTICAL to the openvla rows across all 32 layers and both
      attention columns (64/64 values equal to 6 decimals). The two checkpoints
      are different repos whose safetensors differ by md5, so identical values to
      1e-6 are not physically possible: the openvla_oft block is a relabelled copy
      of the openvla block. RQ4 as shipped measured TWO models, and
      report/paper_acl.tex:255's "Architectural Universality ... across both
      LLaMA-based and SmolLM2-based backbone families" had no third measurement
      behind it.
      ROOT CAUSE (a real script bug, not a transcription slip):
      analyze/attention_extract.py wrote ONE combined CSV and overwrote it on
      every invocation, while the three models require three different conda envs
      and therefore three separate processes — so each per-model run clobbered the
      previous one and recombining was a manual step.
      FIX (commit 50b999b): per-model shards report/rq4_attention_<model>.csv;
      `--merge` builds the combined CSV and REFUSES if two models' rows are
      identical; `--model all` now errors out instead of appearing to work.

  (b) BLANK-IMAGE INPUT — SHIPPED, NOW FIXED. The OpenVLA/OFT path forwarded
      np.zeros((224,224,3)) — an all-black image — while SmolVLA used the real env
      observation. The two families were therefore never comparable, and
      OpenVLA's near-uniform ~0.0039 values (= 1/256, the uniform ceiling) are
      consistent with a degenerate input rather than a finding. This contradicted
      both report/RQ4_RQ5_SPEC.txt:17-18 and the script's own docstring.
      FIX (commit 50b999b): builds the real LIBERO initial observation and applies
      the full runner pipeline (180-degree rotate -> jpeg roundtrip -> lanczos3 to
      224 -> center-crop 0.9), so attention is measured on the exact tensor the
      policy acts on.

  (c) NO PROVENANCE — SHIPPED, NOW FIXED. The RQ4 run appears nowhere in
      MANIFEST.json (grep -c attention -> 0) and left no SLURM log: the CSV, the
      PNG, the plotting script and the paper section all landed in one commit
      (023c7d0) with no run artifact. That is the same unverifiability that let
      the original fabrication through.
      FIX (commit 50b999b): every run appends a kind=rq4_attention record (repo
      sha, node, GPU, slurm job id) to MANIFEST.json. Also removed
      analyze/plot_rq4.py's silent fallback to an ungitted
      /scratch/pandya.kei/rq4_attention.csv.

STATUS: all three fixes are in; the re-measurement itself is BLOCKED on the

Two further items to validate before the paper leans on the magnitudes:
  (a) OpenVLA/OFT use a HARDCODED visual-token span: visual_indices =
      range(40, 296). The measured per-visual-token attention (~0.005) is ABOVE
      the uniform ceiling (1/256 ~= 0.0039), which suggests that span may include
      some non-visual (language) tokens and/or the patch count/offset is off.
      Confirm the true image-token positions from the processor output (decode
      token types) rather than assuming 40..296.
  (b) SmolVLA extractor swaps in an eager VLM via load_state_dict(..., strict=
      False); verify no weights were silently dropped (log missing/unexpected keys).
The AAR is a RATIO, so a consistent mis-span largely cancels and the monotone
noun>verb-with-depth trend is probably robust — but re-run after fixing (a)/(b)
and confirm the trend before citing exact AAR numbers.
